# Rule: Present Divergences First — Don't Silently Change

When reconciling skill docs against the live app, **every divergence must be presented to the user for a decision** before any change is made. No silent edits.

The pattern established in Session 3:
1. Read the skill doc and the live SCSS/component
2. Identify the specific difference
3. Present both options with context
4. User decides: add-to-app or drop-from-skill or update-skill
5. Record the decision in the memory file
6. Implement in a subsequent session (unless the task is trivial/single-file)

This applies to: token values, visual models, variant presence/absence, size systems, sub-component existence, layout approaches.
