# Domain 9 — Reputation

Tables: `review_requests`, `reviews`, `private_feedback`, `review_events`
Enums used: `review_request_status`, `review_event_type`

---

## Lifecycle Overview

```
scheduled  →  sent  →  engaged  →  likely_reviewed   (terminal)
                  │             └→  completed_internal (terminal — rating ≤ 3)
                  └────────────────→ expired           (terminal — 14d window)
```

**Terminal states stop ALL automation.** Workers must filter on
`status NOT IN ('likely_reviewed', 'completed_internal', 'expired')`
before considering a row for a reminder, nudge, or attribution.

Migration `0031` drops and recreates `review_request_status` from scratch with
only the 6 lifecycle states above. There are no legacy values in the database;
the TypeScript `ReviewRequestStatus` union mirrors the enum exactly.

## `review_requests`

A review request sent to a contact after job completion. One per job — structurally enforced.

```sql
CREATE TABLE review_requests (
  id                       UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  org_id                   UUID NOT NULL REFERENCES organizations (id),
  job_id                   UUID NOT NULL REFERENCES jobs (id),
  contact_id               UUID NOT NULL REFERENCES contacts (id),
  status                   review_request_status NOT NULL DEFAULT 'scheduled',
  sent_by_automation       BOOLEAN NOT NULL DEFAULT FALSE,
  sent_by_member_id        UUID REFERENCES org_members (id),

  -- Customer's chosen star rating on the landing page (1–5). Null until submitted.
  submitted_rating         INTEGER CHECK (submitted_rating IS NULL OR
                                          (submitted_rating >= 1 AND submitted_rating <= 5)),

  -- Lifecycle timestamps
  sent_at                  TIMESTAMPTZ,
  engaged_at               TIMESTAMPTZ,           -- set when rating ≥ 4 submitted
  redirected_to_google_at  TIMESTAMPTZ,           -- audit: when redirect issued
  completed_at             TIMESTAMPTZ,           -- terminal: rating ≤ 3
  expired_at               TIMESTAMPTZ,           -- terminal: 14d window elapsed

  -- Engaged-stream nudge counter (0 → 1 → 2; capped at 2)
  nudge_count              INTEGER NOT NULL DEFAULT 0,

  -- Attribution engine outputs (set only on transition to 'likely_reviewed')
  confidence_score         NUMERIC(3,2),          -- 0.00–1.00
  attributed_at            TIMESTAMPTZ,

  -- Legacy / shared
  responded_at             TIMESTAMPTZ,
  token                    TEXT UNIQUE,
  token_expires_at         TIMESTAMPTZ,
  submission_count         INTEGER NOT NULL DEFAULT 0,

  deleted_at               TIMESTAMPTZ,
  created_at               TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at               TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

**Indexes:**

```sql
-- One review request per job, ever. Hard constraint (not partial).
CREATE UNIQUE INDEX idx_review_requests_job_id ON review_requests (job_id);

CREATE INDEX idx_review_requests_org_id     ON review_requests (org_id);
CREATE INDEX idx_review_requests_contact_id ON review_requests (contact_id);

-- Worker hot paths (added 0031)
CREATE INDEX idx_review_requests_engaged_candidates
  ON review_requests (org_id, engaged_at)
  WHERE status = 'engaged' AND attributed_at IS NULL;

CREATE INDEX idx_review_requests_active_sent_at
  ON review_requests (status, sent_at)
  WHERE status IN ('sent', 'engaged');
```

**Notes:**

- `UNIQUE(job_id)` is hard — soft-deleted rows still block a re-create.
- `sent_by_automation = TRUE` + `sent_by_member_id IS NULL` → BullMQ.
- `sent_by_automation = FALSE` + `sent_by_member_id IS NOT NULL` → manual.
- `nudge_count` is monotonic; workers increment under a row-level update guard
  to avoid duplicate sends.

## State Transitions (authoritative)

| From        | To                   | Trigger                                                              |
| ----------- | -------------------- | -------------------------------------------------------------------- |
| `scheduled` | `sent`               | Outbox → SMS dispatch worker, `sent_at = now()`                      |
| `sent`      | `engaged`            | Landing page POST with rating ≥ 4 → `engaged_at = now()`             |
| `sent`      | `completed_internal` | Landing page POST with rating ≤ 3 → `completed_at = now()`           |
| `sent`      | `expired`            | Expiry worker: `sent_at < now() − 14d`                               |
| `engaged`   | `likely_reviewed`    | Attribution engine: matched against Google count Δ                   |
| `engaged`   | `expired`            | Expiry worker: `sent_at < now() − 14d` (engaged but never converted) |

Once a row is in a terminal state, **no worker may emit any further action**.

## Reminder & Nudge Streams

Both streams check the terminal-state guard first. Skip if status is
`likely_reviewed`, `completed_internal`, or `expired`.

### Unengaged stream (anchored to `sent_at`)

- `status = 'sent'` AND `now() − sent_at >= 72h` → send standard reminder
  → emit `reminder_sent` event.
- One-shot. The `review_events` log is the source of truth for "already sent";
  do not add a boolean flag.

### Engaged stream (anchored to `engaged_at`)

- **Nudge 1:** `status = 'engaged'` AND `nudge_count = 0` AND
  `now() − engaged_at >= 24h` → send "finish your review" SMS,
  `UPDATE ... SET nudge_count = 1` (guard on previous value),
  emit `nudge_sent` event with `nudge_number = 1`.
- **Nudge 2:** `status = 'engaged'` AND `nudge_count = 1` AND
  `now() − engaged_at >= 72h` → send second high-impact SMS,
  `UPDATE ... SET nudge_count = 2`, emit `nudge_sent` with `nudge_number = 2`.

The two timelines are non-overlapping (72h post-sent vs 24h/72h post-engaged).

### Expiry

`status IN ('sent','engaged')` AND `now() − sent_at >= 14d`
→ `status = 'expired'`, `expired_at = now()`, emit `expired` event.

## Attribution Engine (Probabilistic)

Triggered when an admin updates the org's Google review count.

```
Δ = new_count − organizations.last_known_review_count
```

**Candidate query (the ONLY query that may flip rows to `likely_reviewed`):**

```sql
SELECT id, engaged_at
  FROM review_requests
 WHERE org_id = $1
   AND status = 'engaged'
   AND submitted_rating >= 4
   AND attributed_at IS NULL
   AND engaged_at >= now() - INTERVAL '72 hours'
 ORDER BY engaged_at DESC;
```

The triple guard `status = 'engaged' AND submitted_rating >= 4 AND
attributed_at IS NULL` is non-negotiable: it prevents double-attribution if an
admin saves the same count twice, and excludes negative/expired rows.

**Matching:**

- `Δ <= 0` → no-op.
- `Δ = 1` → pick closest candidate by `engaged_at` (most recent), confidence `0.9`.
- `Δ > 1` → take top `Δ` candidates by time proximity; confidence scoring:
  closest `0.9`, next `0.6`, remainder `0.3`.
- Fewer candidates than Δ → attribute what exists; the rest is organic.

For each matched row, atomically:

```sql
UPDATE review_requests
   SET status            = 'likely_reviewed',
       confidence_score  = $confidence,
       attributed_at     = now(),
       updated_at        = now()
 WHERE id = $id
   AND status = 'engaged'       -- guards against races
   AND attributed_at IS NULL;
```

Then update `organizations.last_known_review_count` and
`organizations.last_review_check_at`, and emit an `attributed` event per row.

Attribution is **probabilistic**. Never claim exact match in the UI.

## `review_events`

Append-only funnel log. Drives sent → opened → engaged → converted analytics
and provides an audit trail for every state-changing action.

```sql
CREATE TABLE review_events (
  id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  org_id              UUID NOT NULL REFERENCES organizations (id),
  review_request_id   UUID NOT NULL REFERENCES review_requests (id),
  type                review_event_type NOT NULL,
  rating              INTEGER,                          -- set for 'rating_submitted'
  nudge_number        INTEGER,                          -- 1 or 2, set for 'nudge_sent'
  confidence_score    NUMERIC(3,2),                     -- set for 'attributed'
  meta                JSONB NOT NULL DEFAULT '{}'::jsonb,
  created_at          TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_review_events_request_id ON review_events (review_request_id, created_at);
CREATE INDEX idx_review_events_org_id     ON review_events (org_id, created_at DESC);
```

**`review_event_type` enum:**

| Value                  | Emitted when                                              |
| ---------------------- | --------------------------------------------------------- |
| `sent`                 | SMS dispatched (mirror of outbox; not strictly required)  |
| `link_opened`          | Landing page GET with a valid token                       |
| `rating_submitted`     | Customer clicked a star on the landing page               |
| `redirected_to_google` | Rating ≥ 4 → server-side redirect issued                  |
| `reminder_sent`        | Unengaged-stream 72h reminder dispatched                  |
| `nudge_sent`           | Engaged-stream nudge dispatched (`nudge_number = 1 or 2`) |
| `expired`              | Expiry worker flipped row to `expired`                    |
| `attributed`           | Attribution engine flipped row to `likely_reviewed`       |

**`link_opened` rules (specific):**

- Fire on landing page GET when the token is valid (not expired, not deleted).
- Do NOT modify `review_request.status`.
- Do NOT influence reminder / nudge timing.
- Do NOT use for attribution.
- Pure telemetry: funnel visibility and click-through debugging only.

## `reviews`

Received review record — positive outcome of the review funnel (score ≥ 4).
No soft delete. Immutable public review record.

```sql
CREATE TABLE reviews (
  id                        UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  org_id                    UUID NOT NULL REFERENCES organizations (id),
  job_id                    UUID NOT NULL REFERENCES jobs (id),
  contact_id                UUID NOT NULL REFERENCES contacts (id),
  review_request_id         UUID REFERENCES review_requests (id),
  score                     INTEGER NOT NULL CHECK (score >= 4 AND score <= 5),
  platform                  TEXT,
  body                      TEXT,
  review_url                TEXT,
  google_review_link_sent   BOOLEAN NOT NULL DEFAULT FALSE,
  created_at                TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_reviews_org_id     ON reviews (org_id);
CREATE INDEX idx_reviews_job_id     ON reviews (job_id);
CREATE INDEX idx_reviews_contact_id ON reviews (contact_id);
```

- No `deleted_at`, no `updated_at`. Immutable.
- `review_request_id` is nullable — organic reviews allowed.

## `private_feedback`

Private negative feedback captured when rating ≤ 3. Visible only to Admin and
Manager. Never visible to the contact.

```sql
CREATE TABLE private_feedback (
  id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  org_id              UUID NOT NULL REFERENCES organizations (id),
  job_id              UUID NOT NULL REFERENCES jobs (id),
  contact_id          UUID NOT NULL REFERENCES contacts (id),
  review_request_id   UUID REFERENCES review_requests (id),
  score               INTEGER NOT NULL CHECK (score >= 1 AND score <= 3),
  body                TEXT,
  is_resolved         BOOLEAN NOT NULL DEFAULT FALSE,
  resolved_by         UUID REFERENCES org_members (id),
  resolved_at         TIMESTAMPTZ,
  deleted_at          TIMESTAMPTZ,
  created_at          TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at          TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

## `organizations` — Google review baseline

Two columns power the attribution engine:

| Column                    | Type          | Purpose                                              |
| ------------------------- | ------------- | ---------------------------------------------------- |
| `last_known_review_count` | `INTEGER`     | Admin-supplied baseline. Δ is computed against this. |
| `last_review_check_at`    | `TIMESTAMPTZ` | When the admin last reconciled the count.            |

The Google review page URL is `automation_settings.google_review_link`
(unchanged — do not duplicate on `organizations`).

## Constraints (unchanged)

- One `review_request` per `job_id`.
- Respect `contacts.sms_opt_out`.
- Respect feature flags (`organizations.feature_review_funnel`,
  `organizations.review_funnel_sms_allowed`).
- Outbox → BullMQ for every dispatch. No direct SMS calls from routes.
